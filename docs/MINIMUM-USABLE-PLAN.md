# 第一版最小可用实施计划

计划日期：2026-09-20。2026-09-21 已完成 Windows 首版 M0–M4 验收，包括两个干净环境中的原生 dsh 真模型调用。安装与使用入口见 [最小版本指南](MINIMUM-USABLE.md)，本次证据见 [验收记录](handoff/minimal-acceptance-20260921.json) 和 [模型事件记录](handoff/minimal-model-20260921.json)。下文保留计划依据与原验收边界，最终表仅按实际验证勾选。

## 目标与边界

验收目标：在干净环境安装插件，启动真实 dsh，让真实模型调用 `GetBias`，返回模拟器实际偏压，并留下重启后仍可核对的调用记录。

- 首验环境为 Windows，使用仓库规定的 Node / pnpm，dsh 全套锁定 `0.1.5-rc.2`。其他平台单独报告验证状态。
- 使用 dsh 自带会话界面；本插件不新增专用前端，最小 bundle 不加载现有 `mast-ui-host` / SSE 展示层。
- 第一条闭环只接 `GetBias`。通过后可在同一显式名单内增加 `GetCurrent`、`GetZPosition`；`stm_hello` 用于装载自检，已有 `stm_get_state` 若保留须列入工具清单。
- 模型可用的 STM 能力限定为上述只读工具。不开写技能、通用仪器动词调用器、动态加载全部技能或组合流程。
- 只连接本轮管理的本地 stmsim，使用明确的模拟器配置和实例身份检查；不连接真实仪器、不创建 `profiles/mast-rig`。
- 本轮不升级到 dsh alpha，不等待余下技能迁移，不做 npm 公开发布。2026-09-20 查询时 `latest` / `next` 均为 rc.2，alpha 为 `0.1.6-alpha.2`；这些是当日事实。

## 计划依据

1. 当前 [bundle patch](../packages/bundle/dsh-spm/cordis.patch.yml) 没有装载技能运行层；[技能包](../packages/host/stm-skills/src/index.ts) 只导出实现与适配器。`GetBias` 还需正式组装和注册。
2. [bundle manifest](../packages/bundle/dsh-spm/package.json) 依赖内部 workspace 包。单独 `pack` 不等于完成安装依赖闭包。
3. [记录库](../packages/host/stm-records/src/store.ts) 默认使用 `:memory:`；成功动作记录不保存完整返回数值。[记录适配器](../packages/host/stm-records/src/plugin.ts) 与 dsh 持久工具结果需要共同提供证据。
4. 现有 [工具调度契约测试](../packages/host/stm-skills/contract/probe-session.test.ts) 和 [模拟器接线测试](../packages/host/stm-skills/integration/readback.test.ts) 可以复用，但不能代替安装态、真模型验收。
5. [旧最小运行清单](MINIMUM-RUN-TODO.md) 中“安装是唯一硬阻塞”“GetBias 只差经由真模型验证”不适用于当前源码。本计划将生产接线列为独立实施项；旧清单的历史观察仍保留。

## 阶段与完成条件

| 阶段 | 工作 | 必须留下的结果 |
|---|---|---|
| M0 基线与前置条件 | 保留当前工作树；确认环境、模拟器路径和模型配置；记录构建与相关测试基线 | 可复核的基线、可用条件和缺项清单 |
| M1 独立安装与启动 | 做最小宿主 bundle 和分发构建，先只验证 `stm_hello` 的装载；在独立目录及全新 `DSH_HOME` 安装 | 分发包、依赖清单、实际插件激活和退出证据 |
| M2 只读技能与记录接线 | 装配 `GetBias`、状态、安全服务、看门狗和持久记录；先通过真实工具调度链调用 | 非模型的完整调用通过；失败、卸载、重启有对应验证 |
| M3 模拟器核对 | 安装同一分发产物，连接本轮 stmsim；独立读回与工具返回比较 | 偏压数值、单位、容差和调用来源可核对 |
| M4 真模型与复现 | 用真实 dsh 会话让模型调用 `GetBias`；关闭后重新读取记录；在第二个干净 home 复现 | 真模型工具事件、持久动作记录、模拟器读回及复现说明 |

### M0：固定可复核基线

- 保存提交号、当前未提交改动清单及本轮来源快照；后续打包证据必须绑定实际工作树，不能只写 `HEAD`。
- 如需隔离实施，保留当前已接受的工作树内容；不回滚、提交或覆盖其他工作。
- 确认 `STMSIM_PYTHON` / `STMSIM_ROOT` 指向可用环境，模拟器运行和数据目录与参考源码分离。
- 确认已有模型配置是否可用，报告配置状态，不输出密钥。真模型阶段使用短会话和有限重试，记录模型标识与实际调用量。
- 首轮记录 `pnpm build` 和单元／契约测试基线，既有失败逐项标明。若密钥缺失，继续 M1–M3，M4 明确记为未执行。

### M1：形成真正可安装的交付物

默认方案是一个可安装的 `.tgz`：分发构建将本仓内部代码收入发布产物；dsh / Cordis 保持外部依赖，Node 内建模块不打包。源码构建仍保留 `tsc -b` 类型检查。

- 新增最小宿主入口和 patch，复用现有 provider，保留现有完整 bundle 的用途。
- 发布 manifest 从来源生成，精确声明所需外部依赖；保留各子包的私有状态，不依赖公开 registry 中存在本仓内部包。
- 先以 hello 冒烟验证打包方案。检查 ESM、子路径导出、运行时资源，以及 `createRequire(import.meta.url)` 读取 manifest 的相对路径。
- 将产物复制到仓库之外的临时目录。该目录不得通过 `link:`、`workspace:`、源码绝对路径或指向仓库的软链接加载本仓代码。
- 在独立安装环境锁住实际可达的 dsh 包树；分别检查版本一致性和运行时模块身份，不把“同版本”当成“同实例”。
- 检查实际插件激活与服务可用；`--dump-config` 只作为配置证据，不单独算启动通过。
- 若单包方案在首轮发现无法可靠处理资源／模块身份，改为完整内部 tarball 集合和本地安装脚本，并沿用上述隔离验收。必须交付完整依赖闭包，不临时转为本地源码链接。

### M2：把现有技能接成正式运行链路

正式链路为：dsh 工具调用 → `defineSkillTool` → `SkillKernel` → 仪器服务 → stmsim；调用结果同时进入 dsh 会话和记录库。

- 在最小宿主运行入口组装 kernel，连接状态快照／刷新、`safeCall`、看门狗中止状态、安全判定和记录回调。
- 复用现有技能的参数、单位、返回格式、拒绝文案，不复制一份绕过 kernel 的 `GetBias`。
- 按显式名单注册技能与安全声明；必要服务缺失时不激活技能入口。验证模型工具目录中的 STM 集合，并检查不存在写技能和任意技能分发入口。
- 核查 provider 对应本轮启动的模拟器；`simulated: true` 只是声明，仍需配合受控启动、进程及端口归属验证。拒绝未知既有端口占用。
- SQLite 使用临时 profile 数据目录中的明确文件路径。启动时验证能创建并写入；写入失败必须可观察，验收程序不能将“工具成功、没有记录”判为通过。
- 保留 dsh 的持久工具结果，以工具调用标识关联 SQLite 动作记录。第一版不更改既有记录 schema 来伪装已经保存读数；若同版 dsh 无法可靠保存／关联结果，补充带调用标识的本地结果文件。
- 工具注册与监听器使用生命周期清理。核查关闭时的在途调用、TCP 连接、SQLite 句柄和模拟器进程，确保卸载／退出后端口释放，重启无重复注册。

### M3：先完成可重复的模拟器验证

- 测试装载 M1 的安装产物，调用真实 dsh 工具调度入口；不能只直接执行 `GetBias.execute()`。
- 由验收夹具控制模拟器偏压，独立于技能／模型直接读取 `Bias_Get` 作为对照。改变夹具值后再次读取，排除固定返回值和缓存冒充实时读数。
- 比较返回值是否为有限数、单位是否为 V，并按 float32 传输声明容差。受控偏压设置只属于模拟器验收夹具，不注册为模型工具。
- 至少覆盖断链时返回失败、不把旧值当成功，以及相应失败记录可以查询。
- 关闭宿主，用新进程重新打开 SQLite 和会话记录，核对成功与失败调用仍在。内存账本不能代替该检查。
- 核查调用日志时区分后台状态轮询、看门狗动作与模型发起的技能调用；不能将轮询中的 `Bias_Get` 误算为模型调用证据。

### M4：让真实模型完成用户验收句

- 使用固定版 dsh 的原生会话入口和可用模型；首先确认 `stm_hello` 可被调用，再让模型实际调用 `GetBias`。
- 保存原始工具调用及返回事件。模型从状态提示中复述一个偏压，或仅声称“已调用”，均不算通过。
- 核对同一次调用的工具标识、真实仪器请求、返回数值、SQLite 动作记录；数值与模拟器独立读回相符。
- 关闭后从磁盘重读证据，再用第二个全新 `DSH_HOME` 复现安装和模型读数。测试结果注明模型与版本、模拟器版本／配置、Node、操作系统和实际命令。
- 最终交付安装包、安装／启动方法、检查与清理入口、脱敏验收记录，以及一张逐项勾选的验收表。

## 验证安排

- 来源构建：`pnpm build`。
- 单元／契约：`pnpm test --project unit --project contract`，重点新增最小运行入口、工具名单、记录与生命周期判据。
- 模拟器：显式配置环境后执行受影响的 integration 测试，并新增对安装产物的完整调度验收。使用已确认空闲的本地端口，不与另一轮模拟器测试同时运行。
- 分发与真模型验收独立于上述测试，分别报告；不把测试替身、源码别名导入或历史测试数量当成安装态证据。
- 若修改了规格或技能源注册表，遵循 `gen:skills` → `build` → `gen:progress`；仅新增运行时名单不应篡改迁移计数。
- 既有跨平台失败保留基线对照。相关新增／回归问题必须解决；无法验证的条件明确记为缺项，不跳过后报通过。

## 时间预算与先后顺序

初步预算为 2–5 个工作日，前提是依赖、模拟器及模型配置可用。

- 第 1 天：M0 与 M1，先消除分发和真实宿主装载的不确定性。
- 第 2 天：M2，完成 `GetBias`、必要服务及磁盘记录接线。
- 第 3 天：M3 与首次 M4，完成独立数值核对和真模型调用。
- 第 4–5 天：用于安装依赖、生命周期或模型可见性问题的修复，以及干净环境复现、交付整理。

M1 完成后重新估算剩余工期；上游安装机制问题、不可用的模拟器或缺少模型配置应单列为阻塞。运行入口与分发研究可以并行，写共享 bundle／manifest 前必须分配文件职责。最终模拟器和安装验收按顺序执行。
